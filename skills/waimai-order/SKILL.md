# 通用外卖点单

通过浏览器自动化在饿了么 H5 上完成选店、选菜、加购和提交，支付环节按插件配置决定人工或自动。

## 前置条件

插件已挂载外卖 MCP 工具，命名空间为 `mcp__waimai__*`：

`open_browser`、`search_food`、`enter_shop`、`get_menu`、`claim_coupons`、`apply_coupons`、`add_to_cart`、`view_cart`、`submit_order`、`request_payment`、`get_order_status`。

浏览器是有头窗口，登录和验证码由用户在窗口里完成。所有工具返回 `{ success, data }` 结构的 JSON。

## 操作流程

1. **确认需求**：问清想吃什么、口味、预算。用户没给配送地址就先问地址——地址由用户在页面里选择，Agent 不要臆造。
2. **打开页面**：调用 `mcp__waimai__open_browser`。若返回的页面提示登录，请用户在弹出的浏览器窗口中完成登录，然后继续。
3. **搜索**：调用 `mcp__waimai__search_food`，参数 `keyword` 用用户的原话（如「奶茶」「盖饭」）。
4. **推荐**：把 `data.shops` 里的店铺名、评分、配送时间、起送价列给用户，等用户选择。不要替用户决定。
5. **进店与菜单**：调用 `mcp__waimai__enter_shop`（`shopName` 用搜索结果里的原文），再调用 `mcp__waimai__get_menu`，把菜品名和价格列给用户。
6. **加购**：用户选定后调用 `mcp__waimai__add_to_cart`（`itemName` 用菜单原文，`quantity` 可选）。未达起送价时如实告知，并询问是否凑单。
   进店后可调用 `mcp__waimai__claim_coupons`，只领取配置允许的免费券；结算自动按 `autoUseCoupons` 选择可用券并重读实付金额。两个勾选项默认开启，预览模式不操作优惠券。
7. **回显购物车**：调用 `mcp__waimai__view_cart`，把商品、数量、总价、配送费完整列给用户。
8. **提交前确认**：把「店铺 + 菜品 + 数量 + 总价」整理成一行摘要，**等用户明确同意**再调用 `mcp__waimai__submit_order`。
9. **支付**：按返回结果和插件配置处理：
   - 配置为 `manual`：告诉用户「订单已生成，请在浏览器窗口中手动完成支付」。
   - 配置为 `auto`：调用 `mcp__waimai__request_payment`。它会自己从页面读金额和商家并校验，你不需要、也无法传金额。
10. **收尾**：用 `mcp__waimai__get_order_status` 确认最终状态，如实汇报。支付未确认时不要声称已经付款成功。

## 安全护栏

- **支付金额不由你决定**。`request_payment` 没有任何参数：金额和商家由服务端从当前页面读取，再对照配置的上限和白名单校验。不要试图用 `submit_order` 的参数绕过上限——服务端只接受比配置更低的临时上限。
- **每步先核对 `success`**。返回 `success: false` 时把 `error` 原文告诉用户，不要自行猜测原因，也不要反复重试同一个失败操作。
- **写入型操作前必须回显**。加购和提交订单前都要让用户看到商品与价格并得到确认。
- **超限即停止**。金额超过上限时服务端会拒绝提交，此时向用户说明并询问是否手动下单。
- **不代人做决定**。店铺、菜品、地址、份数都由用户确认；菜单里没有的菜品不要编造。
- **页面结构可能过时**。饿了么 H5 的 DOM 会变，工具报「未找到…」时如实反馈并附上截图路径，请用户确认页面现状。
