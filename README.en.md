# dsh-waimai

Taobao checkout and submission send the same Taobao channel header so coupons are priced for the intended channel. A read-only check on 2026-10-26 changed a 570 ml × 24 water quote from ¥49.20 with a ¥10 coupon to ¥48.20 with the already upgraded ¥11 coupon, matching the official app; it created no order or payment. The official upgrade endpoint is `mtop.alibaba.svip.langrisser.act`, using the coupon button's server-issued `extInfo.supplyInst`. Already upgraded coupons need no upgrade request. Missing parameters are never guessed or replaced with membership exchanges. This release corrects quote routing; it does not activate new coupon upgrades.

Taobao checkout and submission diagnostics share a quote reference and distinguish transport failures, platform responses and quote validation results. Logs retain structured protocol status and amounts without remote messages, order payloads, addresses or payment links. Live purchasing still requires verification with the current account.

Hema delivery store IDs are normalized before address checks, so reordered IDs do not invalidate checkout; changed store membership still stops submission. Order diagnostics retain structured return codes without remote messages, credentials or payment links. Unknown outcomes retain the original attempt and block duplicate submission.

A DeepSeek Harness plugin for Taobao Instant Commerce and Hema. Account-scoped HTTP provides sign-in, addresses, history, products and carts. Hema supports integer SKU additions, verified checkout quotes and confirmed order creation; payment continues in the official app. Meituan and JD are not integrated.

QR accounts show the Taobao display nickname and self portrait from the same authenticated session. A portrait with another native nickname is rejected. Missing or failed portraits use the nickname initial with a refresh notice. Account IDs remain in account details; an absent nickname uses the unnamed-account label. Both the Taobao identity and ordering identity are checked around the read; changed identities stop profile display.

Each platform declares its login methods and default entry. Taobao provides QR and SMS. Hema defaults to SMS through Taobao authorization, with QR authorization and explicit reuse of a signed-in Taobao account as alternatives. SMS uses the official Alibaba account web flow, then verifies the Hema self profile and history independently; it does not claim to use the Hema app device login interface. Registration and additional verification stop the flow. Phone numbers and codes stay in private settings requests. Hema app QR remains unavailable and never silently starts a Taobao QR attempt. Defaults do not claim verified official recommendations. The local account index adds taobao-sms; Hema credential writes use version 2 while version 1 remains readable. Downgrades require restoring pre-upgrade local backups. Credential backups stay on the local machine.

## Agent ordering

Hema products open a specifications modal. get_product_details renders pack sizes, minimum quantity, quantity step, stock and pricing units. Recorded details require a fresh check. Refresh uses the recorded account and its currently selected address; changed identities, invalid references and failed refreshes discard old details. Plugin and conversation controls share SKU and quantity selection, pending feedback and a floating cart modal. Its item list scrolls within the modal so the title and close control remain visible. Success requires a matching SKU quantity delta with every unrelated line retained. Detail refresh and add re-read the original catalog page and store sale status. Closed sale periods and products missing from that page stop additions. Weighted and cross-platform products stop when their native add semantics are unconfirmed.

Agents read get_cart with platformId hema, then add_product_to_cart with productRef, skuId, integer quantity, revision and a stable operationRef. Native additions are sent once. The complete before snapshot and result remain in the private account file hema-cart-attempts.json. Timeouts and delayed readback require only cart reads; reload never resends. An unresolved attempt blocks new additions. Cart display prices do not establish membership discounts, delivery charges or the final amount due.

search_shops returns an opaque nextCursor for nearby merchant pages, including pages with no keyword matches. Positions are bound to the account, query, scope and native delivery selection; reloads, expiry or eviction require restarting from the first page. Advanced settings expose browseCursorSeconds and browseCursorLimit.

search_products reads current menus in up to ten explicitly selected stores. Results retain product names, pack descriptions, listed prices and availability, and declare selected-stores-only scope. Failed stores remain visible with complete: false. Explicit platform empty-store responses display their notice; unexplained or malformed responses remain errors. A case of water requires verification of bottle capacity, bottle count and the actual SKU; listed prices cannot establish the lowest checkout total.

Menu and preparation results use orderingAvailable for interactive ordering, automaticOrderingAvailable: false for disabled automated purchasing, and userConfirmationRequired: true for explicit confirmation.

The public tool.call.toolview slot renders shops, menu recommendations, carts, checkout confirmations and payment handoffs inside the conversation. show_order uses real menu itemIds and an optional budget. Users can choose variants, required extras and quantity, add items, remove one unit and request a quote inside the card. Plugin pages retain their floating cart; chat cards use an inline cart.

Agents can read get_cart and get_item_options, then change_cart with the current revision and validated selection references. Cart changes do not create orders. submit_order requires accountRef, shopId and maxAmount in yuan; it reads the real checkout total and returns a user confirmation card. The card refreshes the quote and checks the account, selected address, cart revision, expiry and budget before submitting. An explicit user confirmation can place a manual order while automation preview stays enabled. Scheduled purchasing remains disabled.

Payment uses the official cashier page opened by the user. request_payment and get_order_status inspect local attempts and matching official orders; they never charge. Opening a URL or receiving HTTP success does not establish payment. Private addresses, credentials and payment URLs stay in authenticated UI RPC and are not included in model tool output. Unknown submissions reserve budget and must not be retried.

## Installation and validation

Optional ingredient groups with zero allowance keep base variants available and disable extras. Zero is never interpreted as unlimited. Contradictory defaults, required extras or quantity rules stop the operation.

Install a fixed Git SHA through the managed DSH plugin installer. The package ships lib/ directly and has no build step. Run npm run check and npm test. Chinese documentation in README.md describes each configuration field, platform API and prior live validation. Migration guidance is in MIGRATION-0.3.0.md.

maxOrderAmount caps each order; dailyBudget caps daily reservations when nonzero. dryRun defaults to automation preview. loginDiagnostics records allowlisted login, cart and order stages without credentials or personal data. Existing local account and order files stay under DSH_HOME/waimai and never belong in environment sync.

Hema checkout resolves serviceable shop and location IDs through ShopDecideApi.decideByAddressId, then calls mtop.wdk.hema.cart.confirm and mtop.trade.order.build. Explicit lineIds and the current cart revision select quote items without changing official cart selections. Each selected product must currently have quantity one. The owner verifies address, SKU, quantity, listed subtotal, discount, shipping breakdown and consistent totals. Extra charges, additional agreements and ambiguous replies stop submission. The quote is shared by the plugin page and Agent confirmation cards.

Checkout selection is separate from phone selection. Only available lines with supported quantities enter the initial checkout selection; unsupported phone selections cannot block another product's quote. Hema delivery choices use mtop.trade.order.adjust for server repricing. A sole available option is selected and verified automatically; multiple choices appear in the plugin and conversation card. Changes replace the quote reference and clear amount confirmation. Missing selections, stale references and inconsistent totals prevent submission. Native delivery IDs and adjustment parameters stay in backend memory.

Confirmed Hema orders use one mtop.trade.order.create request after a shared lock, durable budget reservation and readback. Changed addresses or carts, expired quotes, exceeded limits and duplicates stop before creation. Unknown outcomes stay reserved and are never retried automatically. After checking the official app and confirming that the original request created no order, the user may explicitly authorize one retry from a fresh quote. The server binds it to the original unknown attempt, buyer, address and items, with no increase in amount. Reuse and retry chains are rejected; original records and reservations remain intact. Native parameters and signatures stay in backend memory; complete payment in the Hema app and verify official order status. Live delivery selection, checkout and shipping totals were verified on 2026-10-21. Real creation requests returned no recognizable order ID and the order API showed no matching new order; successful purchasing and payment remain unverified.

## Supermarket orders through the Agent

Version 0.8.5 adds native Taobao Instant Commerce supermarket search, single-SKU cart additions, and checkout. Use search_retail_products, get_retail_cart, add_retail_product, and preview_retail_checkout. After explicit purchase and budget authorization, confirm_order creates one order through the existing account, delivery, budget, and duplicate-attempt checks. Limits apply to the final payable total including delivery after discounts. Products requiring additional properties or SKU selection are not supported for additions yet. request_payment resolves current pending supermarket payment actions in the private chat card; payment URLs never enter model output or persistent logs. Charges still take place in the official cashier.
