# 支付密码能力审查（2026-11-08）

## 当前结论

当前独立 Web 服务不能宣称支持安全保存支付密码后跨平台自动付款。安全保存与实际收银台验证是两个独立验收项；本次没有读取、保存或使用真实支付密码，没有付款。

## 实际代码证据

`lib/payment-credentials.js` 的 `PaymentCredentials` 由 DSH Host 的 `ctx.credentials` 提供存储，仅接受淘宝账号选择，保存为共享 `dsh-waimai/alipay-payment` 记录，调用 `prepareCall` 时在私有参数副本中注入密码；返回界面的是 configured/writable，而不是明文。它并未按真实支付宝账户身份隔离，也不是多平台通用的凭据适配器。

DSH `packages/credentials/credentials-local/src/index.ts` 的写入链为 `renderRecord` 后 `writeFileAtomic(..., mode:0o600)`，文件权限与原子写入不能证明内容已经加密。不能将此实现直接作为满足本次“本机安全加密保存”的依据。`lib/mcp-service.js` 的独立服务只配置 paymentSetup，本机 Web 的 paymentCredential 回调未接通；不能仅把现有密码输入组件插进页面。

`lib/alipay-h5.js` 只对当前 ready 收银台、准确金额和已支持动作处理密码字段，使用当前响应的 RSA 公钥生成每字符密文。短信/身份验证、开通服务、绑新卡、协议或其他未核验动作不走密码替代路径；存在合成响应测试，但没有真实收银台密码付款验收。银行卡与当前收银台的对应也尚未完成。

## 可实施方案的条件

独立服务应使用 Windows CurrentUser DPAPI 加密文件，保存在安装目录外、用户私有数据目录中，原子写入；按支付平台与可验证的真实支付账户身份分开保存，不能仅按购物账号或全局共享密码。设置页提供明确的保存、替换、删除和自动使用开关，默认关闭自动使用；输入只发给本机私有凭据入口，成功后清空，状态只返回是否存在及绑定范围。导出、日志、普通配置、聊天和公开 MCP 参数都不能包含密码。

付款时必须核对用户已授权的实际订单、金额、支付平台、支付账户、默认卡及当前收银台要求，才在最短生命周期内解密；禁止将密码传入命令行、环境变量、URL、通用浏览器脚本或模型可见消息。校验失败/密码错误后停止，不循环试密码，不在平台要求短信或本人验证时尝试替代。未知付款结果只查询原订单。不同平台需各自完成适配与真实验收，不能通过一份通用密码记录推断能力。

DPAPI 只降低静态文件泄露风险：同一 Windows 用户下的恶意程序、拥有后端权限的插件或被攻陷的运行进程仍可能访问解密内容。现有同源检查不是同一用户本机进程之间的权限隔离；启用密码保存前需要独立私有凭据边界和最小调用权限，不能把“本机”或“已加密”写成绝对安全。

在上述身份绑定、独立存储和真实协议验收完成前，保留官方收银台人工密码/验证码验证流程。官方验证后可继续原订单状态查询，但不能宣称无需再次验证或自动支付已实现。
