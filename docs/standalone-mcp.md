# 独立外卖 MCP

当前工作树包含尚未发布的共用前端。已推送的 `eed78e5` 仅包含独立 MCP 服务及 DSH 接入；后续前端的精简打包被本机 Defender/AMSI 阻止，源码与已有产物尚未完成最终一致性验收，不得据此更新正式部署。

`waimai-mcp-service` 独立于 DSH 运行，一个后台进程持有账号、购物车引用、报价和付款会话。DSH 是带私有页面的客户端；其他 Agent 使用同一服务的公开 MCP。平台业务仍由原 AccountPool 和交易模块处理，没有第二份订单实现。

## 启动

安装固定 Git 提交的此包后运行 `waimai-mcp-service`，源码目录也可运行 `npm run start:mcp`。需要兼容已安装 MCP SDK 的 Node.js；本次验证使用本机 Node.js。服务没有 DSH 启动依赖，也不会启动 DSH。

部署环境必须配置：

| 变量 | 内容 |
| --- | --- |
| `WAIMAI_STATE_DIR` | 独立服务的绝对数据目录；初次验收用空目录 |
| `WAIMAI_TOKEN_FILE` | 公开 MCP 令牌文件的绝对路径 |
| `WAIMAI_HOST_TOKEN_FILE` | DSH 私有接口令牌文件的绝对路径 |
| `WAIMAI_PORT` | 本机端口，默认 `3815` |
| `WAIMAI_UI_SESSION_SECONDS` | 浏览器会话有效期，默认 28800 秒，范围 60–86400 |
| `WAIMAI_UI_SESSION_LIMIT` | 同时保留的浏览器会话数，默认 64，范围 1–1024 |
| `DRY_RUN` | 沿用原自动任务预览模式；手动确认下单和付款仍按各自授权与交易校验执行，不把此值当作全局只读开关 |

分别生成两个不同的随机 32 字节 base64url 令牌，保存到仅当前系统用户可读取的文件。不要写入仓库、模型参数、启动命令参数或共享配置。服务拒绝相同令牌、无效格式和相对文件路径；令牌轮换需停止服务、更新文件、重启客户端。端口只绑定 `127.0.0.1`；拒绝浏览器 Origin、错误 Host 和未认证请求，不提供公网监听或 OAuth。

单笔和每日限额等环境变量沿用 `lib/env.js` 对应的变量名，例如 `MAX_ORDER_AMOUNT`、`DAILY_BUDGET`、`CHECKOUT_QUOTE_SECONDS`。独立模式由服务环境拥有这些配置，DSH 设置不修改服务环境；DSH 重载仅重连，不重启服务。DSH 本机的支付 CLI 连接检查不代表独立服务配置已验证。支付密码仍由 DSH credentials 私有注入；公开 Agent 不取得密码注入工具。

## 客户端

支持 Streamable HTTP 的 Agent 连接 `http://127.0.0.1:3815/mcp`，请求头设置 `Authorization: Bearer <公开令牌>`。不同客户端可同时连接，断开不会销毁后台账号会话。认证头应由客户端的私有凭据配置提供。

DSH 插件设置 `mcpServiceUrl=http://127.0.0.1:3815/host` 和 `mcpServiceTokenFile=<Host 令牌文件绝对路径>`。令牌内容不进入普通设置。DSH 私有页面继续完成账号登录、地址选择和支付验证；公开工具仅返回原来的模型可见数据。Host 令牌有私有账号操作权限，不能交给其他 Agent；私有 RPC 仍由 DSH 验证用户会话。服务 URL 留空保留原内置子进程模式，不能在独立服务还持有同一目录时切回内置模式。

纯 MCP 客户端不会获得 DSH 的互动卡片界面；`show_order` 等返回结构化数据，由该客户端展示。

## 共用前端

独立服务的 `http://127.0.0.1:3815/` 提供账号、地址、点餐、跨平台搜索、订单及支付验证页面。本机浏览器直接进入管理页面，无需管理令牌或浏览器会话。服务仅绑定 127.0.0.1，检查准确 Host，所有浏览器 POST 要求同源 Origin，RPC 要求 JSON。MCP 的 /mcp 与 /host 仍分别使用令牌认证。能访问本机服务的本机进程可操作管理接口。

DSH 的外卖插件提供「打开独立页面」，入口为 `/waimai-app/`，沿用 DSH 的会话认证。两处使用同一份构建后的前端和同一个 schema 校验器；它们均通过当前账号拥有者执行操作，不另存账号、地址、购物车或交易账本。DSH 连接独立服务后，页面从服务读取金额上限；本地连接设置仅控制服务地址和令牌文件位置，不再显示一套可编辑的本地预算。

独立页面复用原账号、购物车、结算、订单与 H5 验证组件。它显示服务预算但不提供运行中更改预算或自动任务的入口；预算仍由部署环境配置。它不持久保存支付密码；当前订单的私有付款卡片保留一次性输入与原验证流程。DSH 内置模式仍使用原凭据服务，已有保存的密码不复制到独立服务。身份验证、短信和额外人机验证由用户本人完成。

前端产物随包发布，不需要 DSH 运行即可访问。修改前端后设置 `DSH_UI_PRIMITIVES` 为官方 `@deepseek-ai/dsh-client-ui-primitives` 的 `lib/index.js`，执行 `npm run build:web`；这只用于构建，运行时不读取 DSH 源码。生成的 `lib/web`、上游 MIT 许可及第三方许可与源码一起交付。此次构建使用官方 UI primitives `0.2.2-alpha.2`，现有 DSH 维护源码基线 `9c31e42eafdde0e02f49e6dee83f030924adeef3`。

## 数据与停止

每个数据目录由 `.mcp-owner.lock` 独占；重复启动拒绝，不自动抢锁。正常关闭 stdin、SIGINT 或 SIGTERM 时等待账号操作结束后释放锁；异常终止可能留下锁。遇到遗留锁，先核实记录的 PID、启动时间和实际进程均已结束，再由维护者处理；不能只按 PID 不存在推断付款未发生。

迁入现有 DSH 数据须在旧服务、运行中任务和付款操作完全停止后备份并迁移，不能同时运行旧版本与新服务指向同一目录；旧版本不会识别新锁。本次不自动迁移或复制正式账号凭据。停止前先检查未确认付款，服务重启会失去内存中的 H5 会话和部分查询材料；账本和未知结果记录必须保留，不能用旧备份覆盖后重试。

## 支付状态

用户授权、实时订单金额、预算、引用有效期与防重规则均由现有交易实现校验。公开 `pay_order` 不接受支付密码，额外验证由用户本人处理。`isError`、HTTP 错误、超时或断线都不能推断未扣款，后续仅查原订单，不自动重发。独立 MCP 的连接测试不代表真实下单或扣款通过；真实支付仍未验收。

## 每日付款预算

每日预算在付款前按“当日已确认支付成功金额 + 本次付款金额”检查。创建订单、待支付、失败和未知结果不计为实际支出。支付成功时间写入同一付款账本；旧成功记录没有该字段时沿用其原尝试日期。原下单与支付记录继续保留并防重，未知结果不会因此获得自动重试许可。盒马当前只提供官方支付跳转，本服务不能阻止用户在外部收银台付款，也不将下单金额冒充实际支出。

独立服务将后端已经脱敏的操作阶段、引用、金额、平台错误码和固定错误分类写入自身 stderr 日志，不记录原始平台响应、Cookie 或支付密码。

## 跨平台身份校验

淘宝扫码登录通过官方 UCC 交换取得饿了么业务会话。淘宝账号 ID、饿了么 localId 和 Havana ID 是不同标识，不要求数值相同。交易 Cookie 的买家 ID 必须与已验证的饿了么 Havana ID 一致；不一致时在结算前停止。提交失败仍保留未知交易记录，同时显示经过筛选的平台错误码；错误文本中的地址、电话和令牌不透传。

2026-11-07 的只读复核确认当前交易 Cookie、业务会话和报价地址相互一致，但 UCC 映射复核未返回可确认会话。此结果不能证明存在串号，也不能证明地址提交错误已解决；`B_10006_01_18_026` 的根因及真实下单仍待验证。

餐饮结算现保留饿了么原生 `addressId`，复用平台地址查询取得唯一关联 ID，分别写入 `uicAddressIdForPadding` 和 `selectedUicAddressId`，设置返回链路使用的地址类型，并按 JSON 字符串编码 `checkoutAddressInfo`。报价分别核对原生与关联 ID，不允许缺失、歧义或串号。2026-11-07 修复源码的真实只读结算通过：同一保存地址、葱烤大排面 1 份、3340 分；这不等于真实提交或付款已验收。

## 下单前支付宝认证

支付配置中的「下单前扫码登录」使用支付宝官方独立登录页，无需订单、金额或付款引用，预览模式也可使用。二维码与进度经私有账号 RPC 返回，浏览器 Cookie 由该账号后台持有，以 Windows DPAPI CurrentUser 加密保存到账号数据目录的 `alipay-session.dpapi`，不返回模型或写入普通设置。只有官方受保护页面核验通过才显示已登录；扫码或手机确认本身不代表成功。退出登录删除保存的会话；普通关闭只释放运行资源。重启后恢复并向支付宝重新核验，平台过期时才需重新认证。

后续订单收银台会尝试复用此认证，会话能否用于当前支付仍由支付宝决定。提前认证不保证免除支付密码、短信或风控验证，不创建订单、调用付款接口或预占预算；付款成功仍以原订单官方状态为准。

支付宝登录入口已独立于订单列表，支付配置不再提供待付款订单登录。点击「登录支付宝」打开隔离的官方窗口，正常跟随官方登录与验证跳转；不替换登录返回页。额外认证直接在官方窗口完成，页面持续核对登录状态。

官方扫码可能跳转至 `authsa<数字>.alipay.com/login/` 登录节点；这些 HTTPS 跳转沿用同一浏览器会话，登录节点本身不作为认证成功证据。

登录窗口允许支付宝官方 HTTPS 域内正常跳转，包括登录节点及 `c.alipay.com` 返回页，仍拦截收银台付款接口。认证核验从受保护入口最多跟随六次官方账户页跳转；跳回登录页、验证页或域外不记为已登录。

登录数据使用 `WAIMAI_STATE_DIR` 下对应账号目录，必须保留于安装目录和 Git 仓库之外。重装或升级应用不删除该目录；加密内容绑定当前 Windows 用户。不得将数据目录、凭据或登录截图加入 Git 或发布包。DPAPI 不可用、数据损坏或解密失败时显式报错，不降级为明文。

### 支付宝默认付款方式

支付配置按所选淘宝账号保存支付宝收银台默认付款方式。首次列表来自已完成验证的真实 H5 收银台，不将统一登录页的添加银行卡、花呗或代付入口当作已绑定资金来源。无订单时可以独立登录、查看或清除已有默认方式；普通网页登录不提供资金来源列表，尚无已验证列表时页面说明限制。

选择只保存偏好，不创建订单、不付款。付款前重新读取当前收银台，精确核对提供方标识和脱敏详情并确认选择；失效、歧义、金额变化或额外协议均停止，不自动更换资金来源。配置了默认方式后不走 Agent Pay CLI。私有 RPC `paymentPreferences` 使用当前账号作用域，不向公开 MCP 暴露。

偏好保存在账号私有目录的 `payment-preference.dpapi`，用 Windows CurrentUser DPAPI 加密；正常关闭、升级和保留数据目录的重装不清除它。页面、日志和公开工具不返回提供方标识，当前收银台的临时引用不写入文件。

登录状态刷新会独立复核加密保存的会话；一次未通过验证不会禁止之后重新读取。旧扫码窗口未登录而已保存会话仍有效时，关闭旧窗口并恢复已验证会话，不要求再次扫码。支付配置打开时自动查询状态；网页会话更新后不再复用旧 HTTP cookie jar。

页面启动先读取本机已保存账号，再独立等待远端登录核验；未读到列表时显示处理中，不显示尚未添加账号。已加载的账号索引查询不排在远端登录检查后，付款仍要求原有身份核验。

### 独立服务的官方钱包支付配置

独立 Web 的支付配置可选择 H5 收银台或官方钱包。官方钱包使用 CLI `apply-wallet`、`check-wallet`、`bind-wallet`，无需创建购物订单。普通支付宝网页登录和 H5 资金来源不能证明官方钱包已授权；H5 模式分别展示登录和默认付款方式。授权码只从私有表单传到官方 CLI，不写入配置、日志或模型输入。银行卡和扣款方式在官方支付宝页面管理，不在本服务保存支付密码。

`payment-settings.json` 位于独立服务私有数据目录，保存 provider 和单笔额度，不包含钱包凭据。官方 CLI 自己保存钱包授权。钱包模式保存配置必须先通过官方授权查询；H5 模式保存通道和额度，不表示收银台已验证。Web 与 MCP 的实际下单入口重新检查已保存配置和金额，钱包模式还检查官方授权；H5 的身份与资金来源在付款前重新核对。钱包授权不证明任意商户收银台兼容；最终是否付款成功仍由订单和支付回执核对。当前真实购买仍未验收。

部署通过 `ALIPAY_AGENT_EXECUTABLE` 指定已核验的官方 CLI；`WAIMAI_PAYMENT_SESSION_ID` 为当前已授权购买任务的真实会话 UUID，仅用于独立服务支付调用，不复用其他聊天身份。服务数据目录和官方钱包目录均应保留，升级代码不能清除凭据。

支付设置页在可见时每 5 秒读取官方钱包授权状态，切回页面立即检查；后台检查不清除授权码或覆盖尚未保存的额度，离开设置页后停止轮询。

### H5 MCP payment flow

Payment setup stores `provider=alipay-h5` or `alipay-wallet` with the amount limit. H5 configuration does not require the separate Agent Pay wallet and does not claim that a merchant cashier is authenticated. Existing wallet configurations remain unchanged until explicitly saved.

`pay_order` in the standalone service reads this configuration. For H5 it prepares the original cashier, continues only a verified session, and queries an already submitted payment. The public tools `prepare_h5_payment`, `get_h5_payment_status`, and `continue_h5_payment` never accept cookies, passwords, phone numbers or SMS codes. They return `nextAction`; payment completion must be confirmed with `get_payment_status`.

The private order payment card is available under order history. H5 verification and password entry remain there; independent sign-in and the persisted funding preference remain under payment settings. Automatic continuation requires a saved provider-verified funding preference, fails when that preference is unavailable, and never silently chooses another card. A website login or an H5-ready state is not proof of payment. Real payment acceptance is still outstanding.

支付配置可在无订单时保存支付宝余额或余额宝偏好，保存不代表已验证或可扣款。H5 付款前只匹配当前已验证收银台中的唯一同名独立方式；缺失、重名或需要额外验证时停止，不切换来源。银行卡继续使用验证后返回的具体卡片标识。

已验证：余额/余额宝偏好加密保存，收银台卡片名称与尾号展示，保存卡片在列表重排后的精确匹配，缺失或歧义时停止；109 项相关测试通过。上述测试使用合成付款数据，不是真实银行卡读取或扣款回执。

仍需接入证据：账号绑定记录与收银台扣款选项的可靠对应，以及真实环境下配置完成后再购买的端到端验收。已安装官方 CLI `alipay-bot --help` 未提供银行卡列表命令。官方资料 https://aipay.alipay.com/wallet-guide 说明钱包绑定流程，https://aipay.alipay.com/article/3799 说明收银台可用卡片依赖账户、签约状态和交易条件；它们均不能作为当前适配器已支持无订单读卡的证明。

没有该数据入口时，保持此项未完成；不以“通道已保存”、普通网页登录成功、空卡片列表或单元测试通过替代支付准备完成。

支付设置将购物账号状态与支付宝登录状态分别标注。支付宝状态位于通道与限额上方；查询中、未登录、待验证、已登录、查询失败分别展示，窗口重新获得焦点时重新核查。登录状态或会话变化、窗口重新获得焦点以及可见页面的每分钟检查都会重查付款方式；重复请求合并，后台刷新保留列表和最后确认的默认选择，不重新挂载列表。相同登录状态的轮询不触发额外卡片读取；查询失败显示错误并禁止选择旧引用。保存支付通道及限额不代表登录或付款验证完成。

支付宝登录按钮在后台状态检查期间仍接受一次登录请求，显示等待状态并在检查结束后执行；开始打开窗口时显示进度，离开页面后不执行排队请求。已确认未登录时，窗口焦点变化不再抢先发起重复检查。

付款方式刷新明确展示检查中、成功但无银行卡列表、返回选项数量和失败；空列表不代表支付宝未登录，页面分别提示重新验证、读取失败和已确认无绑定卡。

### 无订单银行卡发现核查更新（2026-11-07）

前述“缺少无订单银行卡来源”的结论已被后续实测纠正。支付宝官方服务大厅“管理所有银行卡”指向 `https://zht.alipay.com/asset/bankList.htm`，页面通过 GET `/asset/bindQuery.json`，参数 `_input_charset=utf-8&providerType=BANK&t=<timestamp>` 读取绑定记录。账号现有会话实测返回 `stat: ok` 和 5 条记录，无订单、无付款请求。

`lib/alipay-bank-cards.js` 已实现并以真实只读响应验证，保留银行代码、名称、四位尾号、卡类型及服务内部绑定标识；不保留姓名、完整卡号、加密卡号或其他响应字段。重定向、非 JSON、异常记录和重复绑定均报告失败，不当作空列表。已接入设置页读取及明确选卡保存：前端仅持有临时选项编号、银行名称、四位尾号和卡类型，绑定标识仅在后端加密保存。保存前重新核对会话与绑定记录；失效选项拒绝保存。这里只证明绑定记录发现和首选卡保存，不证明当前交易可用。

下一验收点为银行卡管理绑定标识与 H5 收银台选项的可靠对应。完成对应前不将发现的卡片自动设为可扣款，也不通过猜测字段或创建测试订单补齐证据。

### 收银台卡片对应证据（2026-11-07）

只读分析官方 `https://maliprod.alipay.com/h5pay/cashierPreConfirm/index.html` 声明的生产资源：公开路径 `https://gw.alipayobjects.com/render/p/yuyan/180020010001207748/`，主脚本 `index.21d242c82.js`，运行时 `runtime.e32322924.js`，收银台页面分块 `7423.11a2445c3.async.js`。该组件展示 `name` 与 `tail`，父选项提交 `selected_channel=value`，子选项提交 `selected_channel=parentValue, child_channel=childValue`，并以返回的 `combinationIndex` 确认选择。

该页面分块未引用 `signId`、`sign_id`、`cardId`、`cardNo`、`bankCode`。此证据不证明服务端响应绝不包含其他标识，也不证明渠道值与绑定关系的对应规则。不能据此把账号管理页 `signId` 当作 `selected_channel` 或 `child_channel`，也不能将合成测试标识视为真实对应证据。

下一步需要真实已验证收银台的脱敏字段结构与管理页绑定记录作受控比较，或建立用户明确确认的卡片对应流程。当前未创建订单、未请求支付或改变账号配置。


银行卡配置回归覆盖：无订单读取与保存、登录变化和解绑后拒绝旧选项、敏感绑定标识不进入页面响应、加密重载，以及绑定标识不得直接用于 H5 渠道选择。绑定卡对应尚未核实期间，页面显示待收银台验证，H5 自动付款明确停止，不替换成其他资金来源。源码测试不代表已安装运行或真实扣款成功。

付款方式使用按行排列的本地图标、名称和选中标记；余额和余额宝使用官方品牌资源，银行卡优先采用平台绑定记录的官方图标，未知或无法安全读取时使用类别图标，刷新入口为带无障碍名称的图标按钮。登录后台检查保留当前状态标题和二维码，避免轮询造成布局闪动。

图标来源、安全限制与实际覆盖见 [支付方式品牌图标](payment-artwork.md)。

登录判定同时要求受保护账户页和同一会话的银行卡账户接口验证通过；仅 HTTP 200 的 HTML 页面不再被当作已登录。有效空绑定列表仍允许确认账户登录，接口异常保留为无法确认，不能推断为可付款。此判定不替代当前订单的收银台验证。

### H5 下单前检查

`get_payment_setup` 的 `policyReady` 只表示已保存通道及有效额度。H5 的 `ready` 不再由通道保存直接置为 true。独立服务在 `confirm_order` 和 `account_submit` 创建新订单前，以同一账号读取支付宝登录和默认付款方式；未登录、状态读取失败、没有默认方式或保存的银行卡已不在当前绑定列表中时返回固定原因并停止下单。银行卡的交易渠道对应在付款前检查，避免首次购买依赖尚不存在的订单收银台。现有订单的准备、验证与结果查询不受新订单检查阻断。

通过这些检查只证明账号层已知条件满足，不保证某笔交易免密、免验证或必然支付成功；订单收银台仍核对可用方式、金额及平台要求。当前银行卡对应与独立密码保存尚未完成，不能宣称完整自动支付已验收。相关测试使用隔离目录和合成状态，不创建真实订单。

登录页面关闭后，若其所属浏览器上下文仍存活，状态检查先验证并保存该上下文，再尝试旧持久会话。仅关闭页面不能直接被解释为退出登录；整个浏览器已退出且会话尚未保存时仍无法恢复未保存的数据。

### 绑定卡在当前收银台的选择

付款前在当前 H5 HTTP 会话重新读取官方绑定卡，核对保存的银行代码、名称、尾号、卡类型和绑定标识全部相同，且名称加尾号在绑定列表唯一。收银台只接受名称和尾号精确匹配的唯一可选项；不猜别名、不把绑定标识当渠道编号、不在缺失或歧义时换卡。选择使用本次返回的渠道字段，原有检查继续确认 combinationIndex 和金额，之后才允许提交。无法在收银台会话读卡或不能精确对应时停止付款。

这是有条件的实现路径：合成测试覆盖唯一匹配、跨会话绑定变化、同尾号歧义、缺失选项、金额变化及无扣款选卡。真实收银台是否能通过这些条件、支付是否成功仍待实际验收，不能从测试通过推出已经完成购买。
