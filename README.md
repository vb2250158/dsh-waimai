# dsh-waimai

DeepSeek Harness 多平台外卖插件。淘宝闪购和盒马通过 HTTP 读取账号、配送地址、历史订单与商品，不模拟 H5 点餐。当前尚未开放创建订单和支付；美团、京东尚未接入。

## 插件页面

顶部统一选择平台和账号，账号选项标明淘宝扫码或短信登录；五个页签共用当前账号视图。淘宝闪购沿用 ele.me 的业务接口域名，页面使用淘宝闪购品牌。

- **账号与地址**：优先显示登录状态、头像、昵称、账号 ID、脱敏手机号和当前配送地址；其他地址折叠为可展开列表。已登录时隐藏登录表单，点击「添加账号」后默认淘宝扫码，也可选手机号短信；短信入口提示订单可能属于不同账号。复核业务账号、资料和订单后才加入列表。多个账号保持独立登录，下拉只改变当前页面视图，不影响其他窗口或任务；切到任务或设置后返回仍保留所选账号。地址选择与账号绑定。
- **点餐**：顶部选择或更改当前账号的配送地址，未选有效地址时不查询店铺。选择后自动加载附近推荐店铺，展示图片、评分、月售、距离、配送时间和起送价，支持翻页及本页名称筛选；也可查看最近一页订单里的店铺。点击「查看菜单」读取分类、菜品图片、标价、售罄状态和只读口味选项，支持菜品搜索。切换地址立即清空店铺和菜单并丢弃旧请求；同地址刷新失败保留已读结果并提供重试。下单和支付仍未开放。
- **历史订单**：优先显示商家、状态、时间、餐品和金额；订单号按需展开。支持刷新、下一页和返回最新记录；每次成功翻页替换当前列表，普通刷新失败时保留最后已校验的页面并显示重试入口，账号不一致时清除资料。
- **任务**：显示当前平台的任务，设置时间、日期、参考菜单与预算。新任务暂停，预览不购买；关闭预览的任务报告接口未验证并停止。
- **设置**：优先显示默认平台、预览和金额上限；尚未开放的购买配置与本机登录、历史分页设置按需展开。页面通过 Host 表单的版本检查保存修改，保留未编辑字段。

未接入平台显示明确空状态，不读取淘宝账号或发送登录请求。切换平台或账号视图时销毁旧资料、地址、订单和店铺列表并丢弃迟到的请求。账号会话按平台和账号隔离，不同账号可并行读取；每个平台同一时间只保留一个待完成登录。默认账号数上限为 10，可配置到 100。美团和京东登录接口仍未接入，不能因多账号界面可用而视为其登录可用。

## 当前能力

| 平台 | 登录/账号 | 地址/历史 | 店铺/菜单 | 结算/创建订单/支付 |
| --- | --- | --- | --- | --- |
| 淘宝闪购 | HTTP 可用 | HTTP 可用 | 附近推荐分页、最近订单店铺、分类菜单 HTTP 可用 | 尚未验证，禁用 |
| 盒马 | 淘宝扫码或明确选择已登录淘宝账号 | HTTP 可用，订单分页 | 配送门店、商品名称搜索分页、规格与只读购物车 | 尚未验证，禁用 |
| 美团外卖 | 尚未接入 | 尚未接入 | 尚未接入 | 禁用 |
| 京东外卖 | 尚未接入 | 尚未接入 | 尚未接入 | 禁用 |

接口字段来自 2026-10-11 的真实账号只读抓包与客户端代码。登录初始化读取 `/mini_login.htm` 中的 JSON，再调用 `/newlogin/sms/send.do` 与 `/newlogin/sms/login.do`，每次发送前获取新 CSRF。登录返回经过 HTTPS 域名限制的 Cookie 同步地址，再通过 `mtop.alsc.user.session.ele.check` 独立确认账号。账号资料、地址和订单每次读取均复核会话与账号。

盒马在平台下拉中单独选择。添加账号可用淘宝 App 扫码，也可点击「使用已登录淘宝账号」并明确选择已保存的扫码账号；不支持未经验证的盒马短信登录。入口先复核来源淘宝身份，再复制限定淘宝域名的 Cookie 到独立盒马会话，依次确认淘宝身份、盒马本人资料和订单；失败不加入列表。不会读取手机私有目录，也不调用注册、绑定、换绑或购买接口。已有闪购账号的 Cookie 文件、默认账号和配送选择保持原样。

盒马资料通过 `mtop.wdk.iseeku.user.profile.get` 读取，必须返回本人资料；头像只使用经过校验的 HTTPS 图片 CDN。地址来自 `mtop.wdk.lbs.location.UserAddressReadApi.getAllAddress`，配送门店由当前已选地址的 `decidedShopData.groupList` 确认；不将它们标成外卖附近推荐。订单使用 `mtop.hema.trade.order.buyer.list.search`，保留超出 JavaScript 安全整数范围的完整订单号，金额由分转元，订单时间按中国时区解析，分页与盒马账号绑定。每次私人读取前后复核身份。

「门店与商品」选择配送门店后输入商品名称，调用 `mtop.wdk.search.item` 分页读取商品、标价单位、图片和库存状态；商品所属原生门店必须位于当前地址的配送组。成功翻页替换当前列表，失败保留最后已确认的一页；可返回首批。分页令牌只在后端保存，页面及模型仅获得与账号、地址、门店和搜索词绑定的随机引用。每个会话最多保留 32 个分页引用、1000 个商品引用；单次搜索超过 1000 件时要求更具体的搜索词，过期引用须重新搜索。

「查看规格」通过 `mtop.wdk.detail.openservice` 核对商品和原生门店，显示当前标价、销售规格、最低数量、数量步长、库存及计价单位。商品搜索标价与规格接口标价可能不同，均不代表结算实付。搜索词建议、跟踪数据、购物车动作、动态签名和购买链接不进入显示结果。

盒马头像和商品图片仅接受允许的图片 CDN；接口返回的协议相对地址和 HTTP 图片地址转换为 HTTPS，仍拒绝含凭据、非默认端口、查询参数及外部主机的图片。

「查看购物车」通过新版 `mtop.trade.query.bag` 按所选地址读取当前账号购物车，显示数量、标价及单位、手机已勾选状态和不可售原因，不修改商品或选择。旧购物车接口的空返回不能证明购物车为空；新版组件层级或商品无法完整确认时明确报错。列表分批展开，刷新失败保留已读列表，账号或地址变化后清空。分类菜单仍属于闪购；盒马结算、修改购物车、下单与支付未开放。2026-10-11 已核对真实账号两批共 57 件商品，无重复，并读取规格及与手机一致的 40 条购物车记录。

附近推荐通过 `mtop.alsc.eleme.miniapp.homepagev1` 与 `mtop.alsc.eleme.miniapp.collection.homepagev1` HTTP POST 按已选地址查询。仅将明确的 `isAd: true` 或 `isAd: "true"` 视为推广，默认过滤；在「点单设置」关闭「隐藏推广店铺」并保存后，展示推广店铺和广告标签，`"false"` 和空广告信息不影响普通店铺；整页推广被过滤时保留下一页入口。分页位置按未过滤的原始页计算，与账号、地址绑定，不接受任意查询参数。菜单使用 `mtop.alsc.waimai.store.miniapp.store.detail.body.query.v2` HTTP POST；折叠菜品的原始商家 ID 必须由菜单中相同菜品的已确认商家引用核对，其他商家内容拒绝展示。只返回图片、菜品与选项等展示字段，不返回购买链接、购物车动作、历史重购记录或跟踪数据。菜单标价不代表实付金额。人工验证时停止；不会执行创建订单、取消订单、购买券包或扣款。

淘宝二维码通过官方 `/havanaone/loginLegacy/qrCode/generate.do` 获取，并轮询 `/havanaone/loginLegacy/qrCode/query.do`。二维码在后端生成 PNG，临时令牌与 Cookie 不返回页面。每次扫码使用独立会话，取消、过期或切换页签会停止检查。淘宝确认后，通过 `mtop.alibaba.ucc.taobao.apply.usertoken` 与 `mtop.alibaba.ucc.oauthLogin` 换取闪购业务会话。仅接受 Eleme 站点的已确认会话，校验 Cookie 域名及账号 ID，再用业务接口复核本地 ID、Havana ID、资料与订单，全部通过后才保存。授权失败或额外验证时保留原账号；注册、绑定、换绑接口不会自动调用。

手机号登录的订单可能与淘宝账号所关联的闪购账号不同，仅改变订单查询渠道不能证明账号一致。2026-10-11 的真实验收已取得淘宝扫码对应的闪购会话，读取昵称、头像与当日订单，并与原短信账号分别保存。平台可能不提供手机号，此时不显示手机号，仍显示已校验的账号资料。额外验证与购买流程尚未验收。

## 安装与开发

```bash
npm install
npm run check
npm test
dsh plugin --profile web add --save-exact github:vb2250158/dsh-waimai#<40位提交>
```

插件没有构建步骤，`lib/` 就是发布产物。普通登录与账号读取无需安装或打开 Chromium；人工平台验证由用户在官方窗口完成。MCP 子进程由 Host 使用包内绝对路径启动，配置变更后重启该子进程。

## 工具

模型工具：`list_platforms`、`list_connections`、`get_status`、`prepare_ordering`、`search_shops`、`get_menu`、`get_product_details`、`preview_checkout`、`submit_order`、`request_payment` 和 Host 的 `preview_task`。`list_connections` 只返回平台和本机保存的账号引用，不返回昵称、手机号或凭据；每次使用仍复核会话。浏览器记住上次的平台和各平台账号，刷新或重新进入插件时复核后恢复；仅保存引用，不保存昵称、手机号或登录凭据。浏览器间不同步，清除站点数据后回到默认选择。已移除的账号回到可用默认账号，平台验证或临时查询失败不会改查其他账号。多个账号时，账号工具必须提供对应 `accountRef`，不会按当前页面的选择改变其他调用。`search_shops` 的 `scope` 默认 `nearby`，查询已选地址的首批附近推荐；`recent` 查询最近一页订单店铺，`keyword` 仅筛选本批结果，不能声称搜索平台全量商家。`get_menu` 要求返回的稳定 `shopId` 和该账号已选地址；盒马还须 `keyword`，后续页原样传回 `nextCursor`。`get_product_details` 用搜索结果的 `productRef` 读取盒马规格。模型结果不包含账号 ID、地址或私人平台分页令牌。购买工具在能力未验证时返回结构化错误，不发起购买请求。原有调用迁移见 [0.2.5 迁移说明](MIGRATION-0.2.5.md)。

短信、账号、地址、历史订单和购物车仅在鉴权的 `/waimai-login` RPC 可用，对应 MCP 内部端点不注册给模型。手机号、验证码、Cookie、地址、订单及购物车摘要不会写入插件配置或共享清单。异常消息不返回网络 URL 或令牌。

## 配置

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `defaultPlatform` | `taobao` | 默认平台，另可选 `hema`、`meituan`、`jd` |
| `dryRun` | `true` | 预览模式；关闭后购买仍受能力限制 |
| `persistLogin` | `true` | 本机 Cookie 持久化；关闭则仅当前子进程有效 |
| `maxAccountsPerPlatform` | `10` | 每个平台最多保存的账号数，整数 1–100；重复登录同一身份更新原条目 |
| `loginTimeoutMs` | `20000` | 请求超时毫秒，1000–120000 |
| `smsResendSeconds` | `60` | 验证码发送间隔秒，60–600；结果不明也占用间隔 |
| `qrLifetimeSeconds` | `180` | 单次扫码等待上限秒，整数 60–600；平台可提前使二维码失效 |
| `qrPollSeconds` | `2` | 扫码检查间隔秒，整数 2–15 |
| `browsePageSize` | `10` | 附近店铺每页数量，1–20 |
| `hemaProductPageSize` | `30` | 盒马商品查询每页数量，整数 1–50 |
| `hideSponsoredShops` | `true` | 隐藏推广店铺；可在「点单设置」关闭，保存后保留广告标签展示，查询会等候接口重连完成 |
| `historyPageSize` | `10` | 每页订单条数，整数 1–20 |
| `maxOrderAmount` | `35` | 单笔金额上限，元；任务只能收紧 |
| `dailyBudget` | `0` | 全局每日上限，元；0 表示无限制 |
| `autoTasks` | `[]` | 任务列表，当前只支持预览 |

任务包含唯一非空 `id`、`name`、`platformId`、`enabled`、`triggerTime`（本地 `HH:mm`）、`dateRule`（`workday/weekend/everyday/custom`）、`customDays`、`skipDates`、`menuPool`（每行 `店铺 | 菜品 | 参考价格`）、`menuStrategy`（`rotate/random/history`）、金额限制和通知选项。每分钟轮询，仅触发指定分钟，不补跑错过的任务。同一任务每天只触发一次，先保存触发记录再执行预览或失败通知。

旧浏览器、支付和优惠券字段保留加载兼容，当前不执行相应操作。升级已有调用与任务前阅读 [0.2.0 升级说明](MIGRATION-0.2.0.md)。

## 本机数据

文件均位于 `$DSH_HOME/waimai/`，未设置时使用 `~/.dsh/waimai/`。`accounts.json` 保存按平台分组的账号引用和经过验证的显示资料；昵称、头像与平台账号 ID 属于本机私人缓存，不进入共享配置。凭据和配送地址引用分别在 `accounts/<platform>/<uuid>/login-state.json` 与 `delivery-selection.json`。订单、地址文本、手机号输入、验证码和未确认扫码会话不持久化。每次使用重读平台账号与地址，缓存资料不是会话有效的证明。关闭持久化时不导入已有凭据，也不写账号列表。

首次加载会把旧 `login-state.json` 和配送地址引用复制到一个独立淘宝账号目录，保留原文件；索引成功保存后只使用新账号目录。重复登录已保存身份时刷新该条目，旧凭据文件保留用于恢复。取消添加只清除待完成登录，不删除已有账号或凭据。升级说明见 [0.2.2 多账号说明](MIGRATION-0.2.2.md)。

扫码成功且闪购业务复核通过后，先保存在独立待登录账号目录，再加入账号索引。扫码不读取已有账号的 Cookie，也不会用已有账号的订单冒充扫码账号的订单。含凭据的旧备份只留在本机。

`automation-state.json` 保存触发和预览历史，`notifications.jsonl` 记录任务通知，`mcp-server.log` 为进程日志。既有 `browser-profile/`、截图、支付流水及 `payment-state.json` 保留原处，不会清理未确认的预算占用，也不被用于点餐。含账号数据的运行目录、截图和抓包文件不可随环境同步或发布。

## 验证范围

测试覆盖平台能力隔离、账号与地址一致性、地址更换后的迟到结果、附近分页、菜单展示字段与异常停止、菜单签名与 POST、盒马会话复制失败保留、完整订单号、门店归属、商品分页重复拒绝、规格和数量校验、购物车层级完整性及私人操作字段过滤、预算收紧、任务去重、RPC 鉴权、React 页面及 MCP 进程。真实账号已验证闪购和盒马的头像、资料、地址、历史订单，闪购附近店铺与分类菜单，以及盒马配送门店、两页商品、规格和只读购物车；平台仍可能要求人工验证。盒马新扫码流程复用官方淘宝二维码交换，额外验证与真实新扫码尚未验收。旧加购接口无法稳定与新版购物车对应，读取时触发人工验证；未开放购物车修改。结算、创建订单和支付尚未验证，测试通过不代表真实购买可用。
